# Revisión de calidad y actualización de caja

Verificado el 14 de noviembre de 2026.

## Cambios publicados

- Las acciones de las cuentas de caja permanecen visibles.
- Cupones: selección de promociones vigentes del mismo negocio, con descuento estimado y validación del servidor. No se cambian descuentos después de registrar pagos. Un cupón que cubre el total liquida la cuenta sin inventar un cobro, con turno abierto y auditoría.
- División en 2–10 cuentas, seleccionando cantidades por producto. La cuenta original conserva el remanente. El servidor bloquea cambios concurrentes, cantidades excedidas, cuentas vacías, cuentas con abonos o descuentos y operaciones sin permiso. Todas las divisiones se confirman en una transacción y los reintentos reutilizan la solicitud.
- Calificaciones con selección visual de 1–5 estrellas y comentario opcional.
- Delivery se ofrece según la configuración del restaurante. Se oculta el acceso cuando está deshabilitado; los pedidos existentes y los saldos anteriores siguen disponibles para completar su atención. La creación de pedidos, invitaciones a repartidores y disponibilidad tienen controles en servidor.
- El carrito conserva sus controles, el foco y la posición de desplazamiento al cambiar cantidades. Se bloquea el fondo y se mantiene estable la altura del panel.
- Sesiones: los fallos temporales de conexión permiten reintentar en la pantalla actual. Solo una sesión vencida lleva al acceso.
- Pagos: un retorno de Mercado Pago o HTTP 200 no confirma un pago; se consulta el estado guardado.
- Historial: las respuestas antiguas no reemplazan solicitudes más recientes; los avisos de pedido listo no se repiten con actualizaciones de ubicación.
- Registro y recuperación: captura segura del formulario antes de operaciones asíncronas, prevención de doble envío y recuperación de controles después de errores.
- Etiquetas accesibles y correcciones de navegación, seguimiento y actualización del modo de cocina.

## Validación

- 236 pruebas automatizadas de JavaScript aprobadas.
- 23 suites de base de datos aprobadas con datos de prueba dentro de transacciones revertidas.
- Scripts internos de las pantallas sin errores de sintaxis.
- La revisión de seguridad de Supabase no incorporó nuevos avisos con esta migración.

Las pruebas no ejecutan cargos reales. La verificación de caja y permisos combina pruebas de lógica y operaciones SQL con usuarios temporales; no sustituye una prueba de aceptación en dispositivos de cada rol. La revisión de base de datos conserva los datos operativos e históricos: esta publicación no elimina tablas ni registros reales.
